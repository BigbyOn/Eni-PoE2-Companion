# Интерфейс ИИ-провайдера (подготовка)

В версии **0.1.0 ИИ не подключён**. Ни один байт не покидает компьютер: сетевого клиента в сборке нет. Этот документ описывает шов, к которому позже подключается провайдер (OpenAI, DeepSeek или локальная модель), чтобы интеграция не потребовала переделки приложения.

## Что уже есть

`src/ai.rs`:

- **Реестр провайдеров** `PROVIDERS` с `available: false` в 0.1.0. У каждого: `id`, отображаемое имя, модель по умолчанию, список моделей, ссылка на страницу API-ключей.
- **Задача** `Task`: `analyse_item`, `compare_items`, `review_passives`, `compare_to_build`, `next_upgrades`, `answer`.
- **Локальное описание запроса** `Request`:
  - `task`, `provider`, `model`;
  - `images`: только *ссылки* на локальные файлы (`file`, `kind`, `w`, `h`, `sha256`) — байтов изображения в описании нет;
  - `context`: имя, класс, восхождение, уровень, акт, зона, активный билд, этап, патч.
- **Хранение ключа** через Windows DPAPI (`CryptProtectData` с энтропией приложения), в `state.json` лежит только base64-зашифрованный блоб. Открытым текстом ключ не сохраняется никогда; в репозитории его нет и быть не может.
- Команда `ai_prepare(ids, task)` пишет рядом со скриншотами `ai-request-<время>.json` — это и есть «подготовка изображения к анализу»: файл-манифест, который будущий провайдер прочитает сам.

## Что появится в следующей версии

```
UI (Скриншоты → «Анализ ИИ»)
        │  invoke ai_analyse(task, shot_ids, question)
        ▼
src/ai.rs: prepare(...)  ──►  Provider::complete(Request) ──► HTTPS
        ▲                              │
        │                              ▼
локальные PNG + метаданные      ответ (текст/структура)
```

1. `Provider` — трейт с одним методом `complete(&Request) -> Result<Answer, AiError>`.
2. Реализации `OpenAi`, `DeepSeek` — обычный HTTPS POST на `/v1/chat/completions`, ключ берётся из DPAPI, изображения кодируются в base64 *в момент запроса* (не хранятся в JSON).
3. Ответ рендерится в разделе «Скриншоты» и (опционально) в оверлее.
4. Пользователь включает провайдера в настройках; по умолчанию всё выключено.
5. Никакой автоматизации игры: ИИ только читает снимки и отвечает текстом.

## Требования к будущей реализации

- Явное согласие: без включённого провайдера и введённого ключа — ни одного запроса.
- Минимизация: отправляются только выбранные снимки и поля контекста; журнал и история — никогда, если пользователь не выбрал их явно.
- Прозрачность: перед отправкой показывается, что именно уйдёт.
- Безопасность: ключ — только DPAPI; логи не содержат ключ; таймауты и ограничение размера ответа.
- Офлайн-режим остаётся полностью работоспособным.
- Никаких «тихих» запросов при старте, обновлении или сборе статистики.

## Почему не сейчас

Задача первой версии — рабочий офлайн-помощник и проверяемая база. Отправка изображений в сторонний сервис — это решение пользователя, а не поведение по умолчанию. Поэтому в 0.1.0 есть только локальная подготовка запроса и безопасное хранение ключа.
