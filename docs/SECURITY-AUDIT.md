Дата: 2026-11-12. Аудит проведён до и во время доработки проекта. Проверялись исходный репозиторий [poe2overlay](https://github.com/maluramichael/poe2overlay), его конфигурация, зависимости и все изменения Eni-PoE2-Companion.

## 3. Изменения Eni-PoE2-Companion и их обоснование

### 3.1 Сеть

**Сетевых запросов в 0.1.0 нет вообще.** Удалены `ureq` и загрузка маршрута. Это устраняет целый класс рисков (MITM, подмена данных, утечка факта запуска). Обновление данных — вместе с релизом.

ИИ-провайдер не подключён: `ProviderInfo::available == false`, ключ хранится зашифрованным, но ни одного вызова нет.

### 3.2 Внешние ссылки

`link_open(url)`:
- только `https://`;
- хост обязан входить в белый список (`mobalytics.gg`, `pathofexile.com`, `poe2speedrun.malura.de`, `github.com`, `raw.githubusercontent.com`, `maxroll.gg`);
- строка с `@` в хосте отклоняется (защита от `user@host`);
- запуск через `ShellExecuteW("open", url)`, без конкатенации командной строки;
- ошибка возвращается в UI.

### 3.3 Запуск процессов

| Место | Аргументы | Риск |
|---|---|---|
| `Store::reveal` / `reveal_data_dir` | `explorer.exe` + один путь (папка скриншотов / данных) | Путь формируется приложением из настроек; командная строка не собирается, shell не используется |
| `link_open` | `ShellExecuteW` с URL из белого списка | Только https и доверенные хосты |

Других запусков процессов нет.

### 3.4 Файловая система

- Чтение: только файл журнала (путь из настроек с проверкой), `state.json`, пользовательские билды, собственные PNG/миниатюры.
- Запись: `state.json` (атомарно), скриншоты и миниатюры (имена генерирует приложение), экспорт истории в `Документы\Eni-PoE2-Companion`, `ai-request-*.json` в папке скриншотов.
- Имена файлов скриншотов, прочитанные из `state.json`, проверяются: запрещены `/`, `\`, `..`; при несоответствии запись отбрасывается при загрузке и чтение отклоняется.
- Экспорт истории не перезаписывает чужие файлы (имя с датой и временем).

### 3.5 Буфер обмена

Только запись: горячие клавиши и кнопки «Копировать» (диагностика, путь экспорта). Чтения нет, содержимое буфера не логируется.

### 3.6 Скриншоты

- Захват — GDI `BitBlt` с экрана в области клиентского прямоугольника окна игры. Память игры не читается, в процесс игры ничего не внедряется.
- На время снимка оверлей скрывается (флаг `capturing`, поток-трекер не возвращает окно).
- Изображения остаются локально; SHA‑256 фиксируется в метаданных.
- В версии 0.1.0 нет отправки изображений куда-либо; кнопка «Подготовить для ИИ» пишет только JSON-манифест.

### 3.7 Tauri

- `capabilities/default.json`: `core:default` для окон `main` и `overlay`. Плагинов с файловыми/сетевыми/шелл-правами нет.
- Окна создаются в `setup` (`"create": false`), оверлей — `focusable: false`, `alwaysOnTop`, `skipTaskbar`.
- CSP ужесточён (см. таблицу).
- `bundle.windows.nsis.languages`: ru/en; `wix.language`: en-US.

### 3.8 Логи

- В `state.json` не попадают ключи в открытом виде (только DPAPI-блоб), нет паролей и токенов.
- Журнал игры не копируется в приложение; в историю попадают только короткие события (зона, уровень, награда).
- Скриншоты и журналы в репозиторий не попадают (`.gitignore`, отдельные папки).

## 4. Зависимости

`cargo audit` (RustSec, 1490 advisories, 451 пакет в `Cargo.lock`):

```
Scanning Cargo.lock for vulnerabilities (451 crate dependencies)
Crate:     proc-macro-error 1.0.4   Warning: unmaintained   RUSTSEC-2024-0370
Crate:     glib 0.18.5              Warning: unsound        RUSTSEC-2024-0429
warning: 2 allowed warnings found
```

- **Уязвимостей (vulnerabilities) не найдено — 0.**
- `glib` и `proc-macro-error` приходят из Linux/GTK ветки зависимостей Tauri: `cargo tree --target x86_64-pc-windows-msvc` их **не содержит**, в Windows-сборку они не попадают.
- OSV-API даёт по crates.io много ложных срабатываний (возвращает advisory без точных диапазонов версий), поэтому основным инструментом выбран `cargo audit` с базой RustSec.
- Точные версии Tauri закреплены (`=2.12.1`, `tauri-build =2.7.1`, `tauri-plugin-global-shortcut =2.3.2`), `Cargo.lock` закоммичен.

## 5. Модель угроз (кратко)

| Угроза | Митигация |
|---|---|
| Подмена маршрута/билда по сети | сетевых загрузок нет; данные встроены и проверяются схемой при старте |
| Вредоносный `state.json` (ручная правка) | санитизация значений, проверка имён файлов, повреждённый файл не перезаписывается |
| Prompt-injection через содержимое журнала | ИИ не подключён; журнал парсится как данные, не исполняется |
| Утечка ключа API | DPAPI + энтропия приложения; ключ не логируется и не пишется в JSON |
| Перехват фокуса/ввода | оверлей `WS_EX_NOACTIVATE`, никакой эмуляции ввода |
| Произвольный запуск команд | нет shell-команд; `explorer.exe` с фиксированным путём; ссылки через белый список |
| Зависание из-за блокировок | фиксированный порядок захвата, тесты, блокирующие оконные вызовы вне мьютексов |

## 6. Остаточные риски

1. **Неподписанные установщики.** SmartScreen предупреждает; SHA‑256 приложены к релизу. Для продакшена нужен сертификат подписи кода.
2. **Чтение журнала** — путь берётся из настроек; приложение читает только текстовый файл и не исполняет его содержимое.
3. **Сторонние ссылки** открываются в браузере пользователя — ответственность за содержимое сайтов лежит на них.
4. **Захват экрана** в области окна игры: если поверх игры открыто другое приложение, оно попадёт в снимок; снимки остаются локально.
5. **Будущая ИИ-интеграция** потребует отдельного аудита отправляемых данных; сейчас её нет.
