# Архитектура Eni-PoE2-Companion

## Общая схема

```
┌───────────────────────────── main window (WebView2) ─────────────────────────────┐
│ ui/index.html + app.css + i18n.js + app.js   (7 разделов, RU/EN)                 │
└───────────────▲──────────────────────────────────────────────┬───────────────────┘
                │ события "state" / "look"                     │ invoke(cmd, args)
┌───────────────┴──────────────────────────────────────────────▼───────────────────┐
│ src/main.rs — состояние, команды, горячие клавиши, трей, окна                     │
│   Snapshot{saved, runtime}   App{campaign, builds, shared, last_area, …}          │
├───────────┬───────────┬───────────┬───────────┬───────────┬───────────┬──────────┤
│ model.rs  │ logparse  │ tail.rs   │ campaign  │ builds.rs │ screens   │ ai.rs    │
│ state.json│ разбор    │ слежение  │ маршрут,  │ JSON      │ PNG/thumb │ провайдер│
│ профили   │ строк     │ за файлом │ шаг,алиас │ валидация │ SHA-256   │ + DPAPI  │
├───────────┴───────────┴───────────┴───────────┴───────────┴───────────┴──────────┤
│ discover.rs (поиск журнала)   game.rs (окно игры, размещение)   capture.rs (GDI)  │
└──────────────────────────────────────────────────────────────────────────────────┘
┌──────────────────── overlay window (WebView2, focusable:false) ───────────────────┐
│ ui/overlay.html + overlay.css + overlay.js — компактный/стандартный/расширенный  │
└──────────────────────────────────────────────────────────────────────────────────┘
```

## Потоки

| Поток | Что делает | Блокировки |
|---|---|---|
| Главный (Tauri) | команды, окна, горячие клавиши, запись `state.json` | порядок: `campaign` → `snap` → `builds` → `shared` |
| Трекер окна (100 мс) | `FindWindowW`, клиентская область, размещение оверлея, показ/скрытие | `shared` только на время чтения/записи полей; `show/hide` — **вне** блокировки |
| Хвост журнала (250 мс) | `Tailer::poll` → события → `on_log` → `update` | `snap`/`campaign` через `update` |
| Повтор регистрации хоткеев (5 с) | только если что-то не зарегистрировалось | через `run_on_main_thread` |

Правила, выведенные из ошибок в процессе разработки (зафиксированы тестами и кодом):

1. **Один порядок захвата блокировок.** `update` берёт `campaign` → `snap` → `builds` → `shared`. Диагностика берёт их по одному, без вложенности. Обратный порядок уже приводил к зависанию приложения.
2. **Никогда не брать `snap` дважды.** Хранилище скриншотов создаётся из уже захваченного `Snapshot` (`App::store`), а не через метод, который снова лочит мьютекс.
3. **`show()`/`hide()` — только без блокировки.** Эти вызовы ждут главный поток; если их делать под `shared`, а главный поток в этот момент ждёт `shared`, получается взаимная блокировка.
4. **Регистрация хоткеев — только на главном потоке** (в `setup` и в `save_settings`), никогда из обработчика хоткея и не из фонового потока.
5. **Окна создаются в `setup` после `manage()`** (`"create": false` в конфиге): страницы вызывают команды сразу при загрузке.

## Журнал и события

`logparse` превращает строки в события:

| Событие | Пример строки |
|---|---|
| `Scene` | `[SCENE] Set Source [The Riverbank]` / `[Берег реки]` |
| `Area` | `Generating level 6 area "G1_6" with seed …` |
| `Level` | `: Name (Class) is now level 12` / `: Имя (Класс) достигает 7 уровня` |
| `Reward` | `: Name has received +10% to [Resistances\|Cold Resistance].` / `: Игрок Имя получил …` |
| `Opened` | смена/открытие файла (с кодировкой) |
| `Truncated` | файл стал короче |

`tail.rs` хранит байтовое смещение и неполную строку, декодирует **целые** строки (UTF‑8/UTF‑16LE), поэтому многобайтовые символы не рвутся. При открытии проигрываются последние 64 КБ: последние зона, область и уровень (награды не проигрываются, чтобы не двигать маршрут).

Локация → маршрут: `resolve_scene(scene, area_id, aliases)`:
1. имя зоны из журнала через таблицу соответствий;
2. если не найдено — внутренний id области через ту же таблицу (языконезависимо);
3. иначе зона считается неизвестной: оверлей показывает её, шаг не двигается, UI предлагает сопоставление.

## Оверлей

- Окно создаётся без декораций, `alwaysOnTop`, `skipTaskbar`, `focusable: false` → `WS_EX_NOACTIVATE`, фокус игры не перехватывается.
- Размер окна равен отрендеренной панели: JS сообщает размер через `panel_size`, Rust переводит CSS‑px в физические и ставит окно в клиентскую область игры.
- Перетаскивание — по реальной позиции курсора (`GetCursorPos`), а не по координатам страницы.
- При показе/скрытии учитывается активное окно: игра или окно помощника; настройка `only_in_game` отключает это условие.
- `scale` реализован CSS `zoom`, `opacity` — прозрачностью фона панели, поэтому окно остаётся ровно по панели.

## Скриншоты

1. Берётся клиентская область окна игры (физические пиксели).
2. На время снимка оверлей скрывается и ставится флаг `capturing`, чтобы трекер его не вернул.
3. `BitBlt` с экрана в DIB (top-down BGRA), каналы меняются на RGBA.
4. PNG (крейт `png`), миниатюра 320 px (box filter), SHA‑256.
5. Метаданные — в `state.json`, файлы — в папке скриншотов; имена генерируются приложением и проверяются при чтении.

## Безопасность в архитектуре

- Страницы не имеют доступа к файловой системе, сети и процессам: только `invoke` к перечисленным командам и `core:default`.
- Все внешние ссылки идут через `link_open` с белым списком хостов и `https://`.
- Сетевого клиента нет; обновления данных — только с релизом.
- Ключ ИИ — DPAPI, в памяти только на время вызова (в будущем).
- Никакого чтения памяти игры, инъекций и автоматизации ввода.
